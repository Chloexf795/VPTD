# 50 步 static OPD 错误分析

分析日期：2026-09-26。只使用已保存的预测、原始导出和 gold，不启动 GPU、不更改评分、
不删除困难样本。核心结论：工程链路已跑通，但当前数据存在事件目标歧义，
模型主要表现为召回增加同时误报增加；不建议直接沿用当前输入协议扩大训练预算。

## 1. 输入与验收

对比 Qwen3-VL-4B-Instruct 与 static OPD 第 50 步。ACE dev 747 条，SWiG dev
3,263 条。两组预测都经过样本身份、输入哈希和完整样本集合检查；重新计算全部指标，
与已有 metrics 完全一致。分角色计数求和与总体 Arg-C 的 TP、预测数、gold 数完全一致。

复现命令（仓库根目录，需要 NumPy）：

```bash
python3 scripts/analyze_static50.py
```

产物位于 `outputs/error_analysis_static50/`：`analysis.json` 是汇总；
`ace_samples.jsonl`、`swig_samples.jsonl` 是逐样本变化；`*_examples.json` 保留
gold、训练前后解析结果及原始输出；`ace_conflicting_inputs.json` 是输入冲突证据；
`source_export_audit.json` 是上游导出审计；`input_sha256.json` 固定本次输入。

## 2. 优先级最高：ACE 相同输入对应不同标签

在当前开发集发现 **67 组完全相同的 prompt 对应不同 gold，涉及 152/747 条样本
（20.35%）**。这些 ACE 输入均没有图片，所以是模型实际可见输入相同。
747 条数据的 trigger 字段全部为空，具体事件触发词没有提供给模型。

例如 `ace:dev:14:4e6d38b7eb68` 与 `ace:dev:15:4e6d38b7eb68`：

（该样本的句子同时提到 government 和 nation 参与战争；原文保留在本地审计数据中。）

两条输入都要求 Conflict/Attack，提示词和候选实体完全相同，但一条 gold 是 `[]`，
另一条是 `nation → Attacker`。当前输入无法表达为什么两条应有不同答案。
同一句中可能有不同事件实例，也可能存在导出或标注问题；仅凭当前文件不能确定来源。

进一步检查本地上游 `EMNLP2026/dataset/sft_ace_dev.json`：在任何本项目归一化之前，
已经存在同样的 **67 组、152 条**冲突，因此不是评分器或此次训练制造的。
上游 train 5,830 条中也有 **391 组、935 条**同输入异标签现象。
这些原始文件只有 instruction/input/output，缺少恢复事件实例所需的结构化信息。

此前跨 split 重复审计没有覆盖同 split 的同输入异标签；这是本次新增发现。
现有分数保留为旧协议下的实验记录，不擅自删掉冲突样本、合并 gold 或改写分数。
另外，本轮是教师 token 分布蒸馏，并非直接以这些 gold 做监督交叉熵，不能把
训练文件中的标签冲突直接等同于本轮优化器接收了相互矛盾的监督标签。

**下一步应回溯含事件 ID、trigger 文本与位置、论元 span 的原始标注，明确事件目标。**
修复后建立新协议版本，重新运行基线与训练后模型，不能只重测某一方。

## 3. ACE：更遵守约束，但更容易过度抽取

Arg-C 正确预测由 611 增至 642，净增 31；错误预测由 2,003 增至 2,123，净增 120。
按具体实体–角色对追踪：新增正确对 88、丢失正确对 57，新增错误对 734、消除错误对 614。

以下三类错误按当前 gold 与提示词候选集互斥划分，计数之和等于 Arg-C 全部误报：

| 错误类别 | 训练前 | 训练后 | 变化 |
|---|---:|---:|---:|
| 实体不在提示词候选集 | 344 | 126 | −218 |
| 实体在候选集，但不是该样本 gold 论元 | 1,382 | 1,706 | +324 |
| 实体是 gold 论元，但赋予错误角色 | 277 | 291 | +14 |

不符合事件允许角色表的预测由 41 降到 0（该项与上表有交叉，不能相加）。
这说明格式和候选约束学习有所改善，主要瓶颈变成“候选实体是否真正参与目标事件”。
考虑到前述 gold/目标歧义，这些是相对于现有标签的错误，不全部等于语义上错误。

事件层面，Transport 的 Arg-C F1 从 29.57% 升至 34.61%；Attack 从 30.87%
降至 28.79%，且多出 84 个误报。角色层面，Artifact 从 13.56% 升至 32.00%，
Attacker 从 27.97% 降至 23.18%，Target 从 25.68% 降至 21.88%。
在 gold 实体只有一个角色的可判定样本中，Attacker→Target 错配由 20 增至 30，
Target→Attacker 由 8 增至 17，方向性角色混淆没有被解决。

具体例子 `ace:dev:452:5849657d9448`：长句提到 Florida meeting，gold 只有
`Florida → Place`。训练前有 1 个正确、2 个错误预测；训练后把 we、I、Marinello、
Sam Sloan、IRS 等列为 Entity，去重后 13 个预测全错。这是把句中实体泛化为会议参与者的例子。

也有真实改善，如 `ace:dev:91:59b563f079d1` 从空答案变成正确的 `EB → Entity`。
因此不是模型整体失效，而是不同角色、事件和样本的效果互相抵消。

## 4. SWiG：运输类误报增多，角色互换仍存在

Arg-C 正确预测由 2,732 增至 2,760，净增 28；错误预测由 6,214 增至 6,481，
净增 267。Transport 单类就增加 **282 个误报**，超过整体净增量，因为其他类有抵消。
该类 F1 从 32.50% 降至 31.36%。Artifact、Place、Origin 的误报分别增加 125、68、60。

逐预测框诊断（先看有无 IoU≥0.5 的 gold 边，未做一对一占用，因此不直接当作官方 FP）：

| 预测框与 gold 的关系 | 训练前 | 训练后 |
|---|---:|---:|
| 没有任何 IoU≥0.5 的 gold 框 | 4,638 | 4,790 |
| 有 IoU≥0.5 框，但所有对应角色都不匹配 | 1,560 | 1,677 |
| 至少有一个位置与角色都匹配的 gold 框 | 2,748 | 2,774 |

例子 `swig:dev:1919:butting_87.jpg`：训练前两个框和角色都正确；训练后两个框
仍分别定位在原来的两个位置，却把 Attacker 与 Target 对调，Arg-C 从 2/2 正确变为 0/2。
这是根据预测坐标和 gold 的匹配判断，未在本次分析中重新人工查看原图。

例子 `swig:dev:2047:wheeling_85.jpg`：gold 共 3 个框，训练前输出 1 个正确框；
训练后输出 34 个框，其中只有 2 个正确，32 个误报。输出末段连续生成 x 坐标
逐次增加的 Agent 框，呈现机械重复模式。不能据此认定每个框的视觉成因，但应检查
生成停止、重复抑制和结构化输出约束，而不是直接增加输出长度。

两次运行都有 712 条有效 `[]` 答案，而 SWiG gold 均非空；数量相同不代表样本相同。
这个漏检问题也值得单独分析，当前没有把空答案当格式错误或从分母移除。

## 5. 格式错误不是唯一原因

ACE 两次均无无效输出。SWiG 无效数从 103 增到 110：

| 无效原因 | 训练前 | 训练后 |
|---|---:|---:|
| 达到输出 token 上限 | 72 | 63 |
| 无法解析为 JSON 数组 | 22 | 34 |
| 论元缺少有效 role | 9 | 12 |
| 坐标超出合法范围 | 0 | 1 |

61 条由有效变无效，54 条由无效变有效。仅观察两次都有效的 3,099 条共同样本，
Arg-C F1 仍从 35.51% 降到 35.45%，误报净增 212；因此不能把下降全部归因于格式错误。
这个共同子集仅用于诊断，不替代完整集正式分数，也不用于重新选择样本报告更高成绩。

## 6. 目前不能声称收益稳定，也不能归因于视觉原型

做了 2,000 次配对 bootstrap，seed=42。ACE 按规范化句子分组（311 组），同句的
多条样本一起重采样，避免把重复句当独立证据；SWiG 按图片分组（3,263 组）。

| F1 变化 | 观测值（百分点） | 探索性 95% 区间 |
|---|---:|---:|
| ACE Arg-I | +1.23 | [−0.31, +2.67] |
| ACE Arg-C | +0.32 | [−1.24, +1.77] |
| SWiG Arg-I | −0.02 | [−0.91, +0.88] |
| SWiG Arg-C | −0.29 | [−1.02, +0.43] |

区间全部跨 0。它们只反映该预测结果对开发集抽样的敏感性，不包含训练随机种子、
文档内依赖、数据标注问题或多指标比较的不确定性，不能当作正式显著性证明。

ACE 中能匹配训练视觉原型的 666 条样本，Arg-C 增加 0.19 个百分点；未匹配的
81 条增加 1.13 个百分点。两组事件组成不同，且评测均为纯文本，这不是视觉有害的证据，
更不能据此宣称视觉原型有效。仍需要文本自蒸馏与静态视觉蒸馏的同预算对照。

## 7. 建议调整下一步顺序

1. **先修清 ACE 事件实例输入与评测协议。** 找回 trigger/事件 ID/span，区分输入缺失与
   标签冲突；为同输入异标签增加预检。不要任意合并 gold，也不要依据这次 dev 错误直接改标签。
2. **在训练集验证输出约束与过度抽取改进。** 角色、候选实体、合法坐标可做结构约束；
   论元相关性和角色方向性需要独立处理。生成上限或去重规则必须预先固定并同时应用于对照组，
   不能为了提高本次 dev 分数事后筛掉预测。
3. **用固定预算比较文本自蒸馏和静态视觉蒸馏。** 先小规模验收，再扩大训练；既看 F1，
   也看误报、角色互换、重复生成和无效率。本轮没有 SWiG grounding 的直接训练，不能假设其
   定位能力会随 ACE 静态蒸馏自动提升。
4. **静态对照明确后再接完整视频教师。** 将时间信息用于 Attacker/Target 等方向角色验证，
   最后补多随机种子、消融和未用于开发的正式测试集。

本次完成的是错误分析与证据留存，没有修改训练算法、预测或数据，也没有启动新的付费训练。
